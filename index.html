CHAPTER 1

推奨する流れ

時間をかけるべきなのは何を、どう伝えるか。配置や大きさの調整は AI に任せて、修正の指示を出しながら仕上げます。

STEP 1文章で全体を構成する説明の順番と、各スライドで言いたいこと自分
STEP 2チャットAIと推敲する曖昧なところを質問させて直す自分 チャットAI
STEP 3文章をそのまま指示にする配置・デザイン・アニメーションは AIAI
STEP 4修正の指示で仕上げる機械的な確認は AI、中身は自分AI 自分
いきなりスライドを作らない

話の順番や飛躍は、スライドより文章のほうが見つけやすく、直すのも楽です。書いた文章は、そのまま AI への指示になります。

全部を AI 任せにすると、なぜダメか
  • 1枚に詰め込みすぎて、持ち時間内に話しきれない。
  • それらしい図でも、内容とずれている。
  • 一般論の流れになり、自分の研究の主張が見えない。
  • 自分で考えていないので、質疑で答えられない。

CHAPTER 3

3つの作り方

どれも ChatGPT か Claude の月額サブスクリプションが前提です。

①PowerPoint内でAIを使う こんな人におすすめ
  • 既存の PowerPoint 資料を直したい
  • 研究室のテンプレートを使いたい
  • 最後はマウスで直接調整したい
 ②VS Code＋AIコーディングエージェント こんな人におすすめ
  • アニメーションや数式を多く使う
  • VS Code や Git を触ったことがある
  • 利用枠を節約したい
 ③AIのスライド作成機能 こんな人におすすめ
  • 環境構築をしたくない
  • AI と会話するだけで作りたい
  • PowerPoint のファイルで渡したい

①PowerPoint内でAIを使う

PowerPoint のホーム →「アドイン」で「ChatGPT」か「Claude」を検索して追加し、サブスクリプションのアカウントでログインします（ChatGPT for PowerPoint / Claude for PowerPoint）。

長所普段の編集と AI 編集を併用できる。AI が作ったものも普通の図形・テキストとして直せる。
短所複雑な図形操作や、ステップ式のアニメーションは苦手。

②VS Code＋AIコーディングエージェント

VS Code 上の Codex か Claude Code に qmd（Markdown）を書かせ、Quarto で HTML と PDF にします。2章の通し例はこの方法です。

長所テキストの編集だけで完結し、AI が得意で利用枠も少ない。文言は qmd を自分で直せばよく、Git で前の版にも戻せる。
短所座標の微調整は苦手。ただし、はみ出しや重なりは自動検査させれば AI が自分で直す（5章）。

そのまま使える基盤を murata-lab/quarto-html で公開しています。1コマンドでオフラインでも見られる HTML と PDF を出力し、ビルドのたびにはみ出しや重なりを自動検査します。

③AIのスライド作成機能

    
AI との会話からスライドを作り、専用のエディタで直して PowerPoint に書き出します。環境構築が要りません。

    

      
ChatGPT Slides

      
会話や資料からスライドを生成し、テキスト・図形・表を専用エディタで編集。PPTX に書き出せます。

      
Claude Artifacts（Slides）

      
claude.ai で会話や資料からスライドを作り、そのまま編集・発表・PowerPoint への書き出しができます。

      
ChatGPT Work

      
スライド用のフォルダを指定してプロジェクトを作ると、結果がそのフォルダに保存されます。テンプレートの PPTX をフォルダに入れて「これを参照して」と書けば使ってくれます。

    スライド送りとアニメーションを連動させる仕組み
    

      
quarto-html では小さな専用プレイヤーがステップを管理し、アニメーション側は「ステップ数」と「そのステップでの描画」だけを書きます。

      
html/<図名>/main.mjs
registerAnimation({
  steps: 2,
  render(step) {
    // stepだけから描画を決める。0→2や2→0にも対応する。
  }
});

      
    
        
  • ← / → でステップが進み、最後のステップを過ぎると次のページへ。
    • 
        
  • ステップ番号だけで描画が決まるので、戻る操作や途中への移動にも対応できる。
    • 
        
  • PDF には各ページの最後のステップが出力される。
    • 
      

      
雛形は uv run scripts/slides.py animation <図名> で作れます。

CHAPTER 5
仕上げ：修正指示のコツ

  
一発で使えるスライドはまず出てきません。確認基準を先に作り、確認と修正の繰り返しを AI 自身に回させます。


  
修正→ビルド→自動検査→画像で確認→報告
↺ 通らなければ AI が自分で直して繰り返す


  
人が見るのは「中身」だけ

  

    
スクリプト
  • 文字のはみ出し
  • 要素の重なり
  • 文字が小さすぎる

    
AI が画像を見る
  • 図と本文のずれ
  • 余白のバランス
  • 色の見分けにくさ

    
自分
  • 説明が正しいか
  • 話の流れが自然か
  • 時間内に話せるか

  


  
同じようなミスが続くなら、基準にする

  
AI が読むファイルに基準として書き足していくと、発表を重ねるほど最初の生成の質が上がります。

  
AI への指示
今回の修正内容を、今後も守るべきルールとして AGENTS.md に追記して。
機械的に検査できるものは、ビルド時の検査にも追加して。

  

    
ファイル書くこと

    
      
AGENTS.mdどの発表にも共通するルール（作業の順番・使うコマンド・完了の条件）

      
.agents/skills/…/SKILL.mdスライド作成専用の細かい手順と基準

      
decks/<名前>/memo.mdその発表だけの基準（対象読者・公開範囲・例外として認めた重なり）

    
  

  
Claude Code は CLAUDE.md を読むので、CLAUDE.md に @AGENTS.md と1行書けば Codex と同じルールを使えます。


  

    AGENTS.md とスキルの例
    

      
AGENTS.md
# Quartoスライド制作

このリポジトリのスライド制作では .agents/skills/quarto-slides/SKILL.md を読む。
探索は対象の decks/<名前>/memo.md → slides.qmd → 参照される html/ の順に絞る。
スクリプトは uv run。npmは使わない。出力HTML/PDFを直接編集しない。

      
.agents/skills/quarto-slides/SKILL.md（抜粋）
- スライド案の対象読者・結論・説明順・必要なデータを確認する。
  情報が不足する、流れが不自然、公開範囲が不明なら、質問し、回答前にスライドを作り始めない。
- アニメーションの render は任意のstepへ直接移動・巻き戻しできる決定的な描画にする。
- 編集後は必ずビルドを実行し、HTMLとPDFの両方を出力する。失敗を修正して再実行する。
- 完了報告はHTMLとPDFのリンクを短く示す。実行できなかった検証は明記する。

    

  


  

    ループがうまく回らないとき
    

      
    
        
  • 行ったり来たりする：基準同士の矛盾。どちらを優先するか書く。
    • 
        
  • 終わらない：「見やすく」は判定できない。「本文〇pt以上」のように数値にし、「3回で通らなければ止めて報告」と上限も決める。
    • 
        
  • 意図した重なりまで直す：例外としてメモに明記する。
    • 
      

    

  


  
修正指示は「どこを・どう」

  

    
✕ 悪い指示○ 良い指示

    
      
いい感じにして3枚目の右の図を、左の本文と上端をそろえて

      
アニメーションを直して機械Bに2つの作業が同時に入っている。同じ機械で作業が重ならないようにして

      
デザインを変えて図の配置と動きは変えずに、見出し・表・引用の外観だけ青系にして

    
  

  
    
    
  • 変えてほしくないものを書く：AI は頼んでいない部分も「ついでに」直す。
    • 
    
  • 中身の修正はメモから：先に memo.md を直し「メモに合わせて更新して」と頼む。
    • 
    
  • 数値や引用は自分で原典を確認する：AI は自信ありげに間違える。

CHAPTER 6
よくある質問

  

    
図やグラフ、数式はどう入れる？

②は PDF を送るか GitHub Pages で公開（公開範囲に注意）。①・③は PowerPoint のファイルで共有できます。

    
未発表のデータを AI に渡してもいい？

    
研究室や共同研究のルールに従ってください。外部に出せない場合はローカルLLM を使います（②）。
